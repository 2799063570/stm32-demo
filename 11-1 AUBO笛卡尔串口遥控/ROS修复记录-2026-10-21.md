## 修复内容

1. ENABLE服务成功后仍保持armed=false，反馈ACCEPTED及忙标志，继续发布零速度；等待服务返回后新收到的ENABLED_IDLE状态再同时反馈DONE和armed=true。等待上限1秒；输入变化、断链、控制器状态失效/故障、STOP/CANCEL均撤销确认并请求禁用。迟到状态不能重新开放运动。

## Linux端应用与运行

如果ROS运行在另一台机器或虚拟机，需要将上述7个更新文件同步到该机器实际工作空间内，不能只同步launch。先停止点动并禁用，再更新、编译、重启串口桥。

在实际Catkin工作空间根目录：

```bash
source /opt/ros/noetic/setup.bash
catkin_make
source devel/setup.bash
```

如果原Gazebo和点动控制器还在运行，只重启串口桥，端口按实际修改：

```bash
rosnode kill /cartesian_serial_bridge
roslaunch aubo_remote_bridge cartesian_serial_bridge.launch \
  port:=/dev/ttyUSB0 joint_states_topic:=/aubo_i5/joint_states \
  max_speed_mm_s:=10.0
```

从零启动则使用原总入口：

```bash
roslaunch aubo_remote_bridge cartesian_remote_gazebo.launch \
  port:=/dev/ttyUSB0 max_speed_mm_s:=10.0
```

恢复后回中松键、显式ENABLE，等待DONE + ENABLED + HOLD SW后再按住SW拨动。

独立的ROS测试环境可执行：

```bash
catkin_make tests
catkin_make run_tests_aubo_remote_bridge_gtest_cartesian_remote_core_test
rostest aubo_remote_bridge cartesian_serial.test
catkin_test_results
```

不要将合成模型测试与现有同名点动控制器同时运行。实际运动验证仍应检查 `/cartesian_jog/command` 的非零linear及 `/cartesian_jog/state`。
