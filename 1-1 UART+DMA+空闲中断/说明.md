# 1-1 UART + DMA + 空闲中断

## 接线与运行

PA9→USB-TTL RXD，PA10→USB-TTL TXD，GND共地；3.3 V逻辑。115200、8N1、无流控，关闭本地回显。打开本目录 `Project.uvprojx`，编译、下载后复位。

## 代码阅读顺序

`User/main.c` → `Hardware/Serial.h` → `Hardware/Serial.c` → `System/Delay.c`。

| 资源 | 用途 |
|---|---|
| USART1 | PA9/PA10收发，IDLE/ERR中断 |
| DMA1_Channel5 | USART1_RX，256字节循环缓冲，HT/TC/TE中断 |
| DMA1_Channel4 | USART1_TX，普通模式，TC/TE中断 |
| 软件FIFO | 512格，有效511字节，隔离中断与前台处理 |

## 实现流程

1. `Serial_Init()` 初始化串口、DMA和中断。接收DMA开启后持续循环，不在每次IDLE时停DMA、重装计数。
2. DMA半满、全满和USART空闲中断均调用 `Serial_CollectDMA()`，按CNDTR计算新数据区间。
3. 新字节复制进软件FIFO，主循环通过 `Serial_ReadByte()` 消费。ISR与前台用读/写索引和内存屏障交接数据。
4. 主循环最多取128字节，调用 `Serial_SendArrayDMA()` 回显。该函数先复制到内部发送数组，因此局部数组可立即复用。
5. OLED每200ms显示IDLE、收发字节、FIFO丢弃与错误计数，运行中不再周期打印统计。

接收相关中断采用相同抢占优先级，避免DMA读位置被两个ISR嵌套修改。SysTick优先级更高。

## 关键接口

```c
Serial_ReadByte(&Byte);               // 1有数据、0暂无数据
Serial_SendArrayDMA(Data, Length);    // Length=1~256；1启动成功、0忙或参数错误
Serial_GetTxBusy();                   // DMA发送数组是否仍被占用
Serial_GetIdleCount();
Serial_GetDropCount();
Serial_GetErrorCount();
```

DMA发送TC意味着最后一个字节已交给USART数据寄存器，**并不意味着TX引脚最后一位已发送完毕**。若扩展RS485方向控制，应再等USART TC。

## 验证步骤

- 发短字符串，空闲后应收到相同字节，IDLE计数增加。
- 连续发送超过256字节，HT/TC仍应搬运数据。只在启动时打印提示，运行中统计在OLED显示；做二进制比对时先丢弃启动提示。
- 短时大流量与前台处理不及时会使FIFO满，DROP增加；线路错误或DMA传输错误会增加ERROR。
- IDLE通常约为一个字符帧的空闲时间，不等价于任意业务数据包边界。第五个工程在此基础上用换行符解析命令。

## 边界

115200 8N1下，128字节约11.1 ms。必须保证接收DMA的中断服务延迟小于半缓冲区填充时间，不能长时间关闭中断或在同级/高级ISR中阻塞。若DMA已绕过整圈而软件仍未搬运，仅凭CNDTR无法还原丢失数据。此例展示HT/TC/IDLE配合，不承诺无限吞吐或无流控下永不丢数据。

`Serial_SendString/Serial_Printf` 是前台日志接口，有20ms字节等待上限，不在中断里调用。DMA TE后重启接收通道，期间数据可能丢失，并计入ERROR。

## SPI OLED可视化更新

PB3/PB5为SCK/MOSI，PB0/PB1/PB12为CS/DC/RES，详见 [统一OLED说明](../docs/OLED接线与显示.md)。软件FIFO/DMA统计改由OLED每200ms显示，移除了运行中的周期串口日志，避免挤占回显带宽。RX为前台取出字节，TX为成功提交DMA的字节；I/D屏幕字段取模100000，错误非零时首行显示完整错误计数。启动提示仍从串口发一次。OLED分块发送，不在接收ISR内刷屏。
