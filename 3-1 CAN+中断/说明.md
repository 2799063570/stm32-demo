# 3-1 CAN + 中断

## 先用内部回环

`User/Config.h` 中 `CAN_LOOPBACK=1`。不需要CAN收发器，接PA9日志串口，115200 8N1。

每秒向标准ID 0x123发送3字节：`序号 A5 5A`。发送完成中断记录结果，接收FIFO0中断将帧存入队列，主循环打印并比较回环数据。正常预期为TX OK与RX PASS；100ms未收到回环帧会提示超时。

## 资源与流程

- CAN1，PB8 RX / PB9 TX重映射。
- `USB_HP_CAN1_TX_IRQHandler`：发送完成，记录成功/失败并清RQCP。
- `USB_LP_CAN1_RX0_IRQHandler`：接收FIFO0，一次最多取硬件深度3帧，放入软件队列。
- 软件队列8格、有效7帧；软件队列满和硬件FIFO溢出分别计数。
- 过滤器掩码全0，接收所有ID；应用发送标准数据帧，也可打印收到的扩展帧、远程帧信息。

```text
36MHz APB1 / Prescaler 4 / (SyncSeg 1 + BS1 13 + BS2 4) = 500kbit/s
采样点 = 14/18 ≈ 77.8%
```

`MyCAN_Send()` 非阻塞提交一帧，只支持一个尚未完成的应用发送请求。`MyCAN_GetTxResult()` 返回0等待、1成功、2失败并消费结果。`MyCAN_Service()` 由主循环调用，超过50ms会申请取消并报告失败。硬件配置单次尝试，不自动无限重发。

## 改成真实总线

设置 `CAN_LOOPBACK=0`，重新编译和下载。

| STM32 | 兼容3.3 V逻辑的CAN收发器 |
|---|---|
| PB9 / CAN_TX | TXD / D |
| PB8 / CAN_RX | RXD / R |
| 电源、GND | 按模块要求供电，共地 |

CANH接对端CANH，CANL接对端CANL；两个物理末端各120Ω终端。对端同为500kbit/s，处于能应答的正常模式。仅监听的分析仪不会发送ACK，单节点通常无法正常完成发送。MCU逻辑引脚不直接接CANH/CANL。

验证对端收到0x123，并从对端发帧给本板检查RX日志。回环PASS只证明控制器内部路径，不验证收发器和接线。STM32F103的USB/CAN共享资源，本工程不启用USB；引脚重映射也不解除共享资源限制。

## SPI OLED可视化更新

屏幕PB3/PB5、PB0/PB1/PB12与CAN的PB8/PB9不冲突，见 [统一OLED说明](../docs/OLED接线与显示.md)。显示总线模式、成功TX、已消费RX、错误与丢弃。前台每轮最多处理3帧，防止持续CAN输入饿死OLED和发送超时检查。CAN重映射先完成，最后初始化OLED并明确保留SWD，释放PB3。
