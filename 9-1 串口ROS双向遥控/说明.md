# 串口ROS双向遥控：C++桥与Gazebo HOME/ZERO请求

STM32F103C8T6、8MHz晶振、72MHz、SPL V3.5.0、Keil ARMCC5，独立裸机工程。协议v2增加命名位置请求与执行反馈，配套ROS Noetic C++节点；必须同时更新固件与电脑程序。

## 接线与烧录

| 模块引脚 | STM32 |
|---|---|
| 摇杆VCC、GND | 3.3V、GND |
| 摇杆X、Y、SW/Z | PA0、PA1、PA2 |
| OLED VCC、GND | 3.3V、GND |
| OLED CLK/D0、DIN/D1 | PB14、PB15 |
| OLED CS、DC、RES | PB0、PB1、PB12 |
| USB-TTL RXD、TXD、GND | PA9、PA10、GND |

USB-TTL用3.3V逻辑，115200 8N1，无流控，不是RS-232。开发板独立USB供电时转接器只接TX/RX/GND。OLED按SSD1306兼容128×64七针SPI屏实现。

打开Project.uvprojx，F7编译，ST-Link/SWD下载Objects/Project.hex；BOOT0=0。BIN地址0x08000000。

## 操作

1. 上电松开摇杆，约160ms稳定回中校准。
2. 菜单上下选HOME/ZERO；回中后短按并松开确认，只生成一次请求。
3. 左右切换五页：菜单、输入、J1/J2、J3/J4、J5/J6。回中后才能再次导航。
4. 任意页长按约0.8秒发一次CANCEL；长按松开不追加短按。反馈页短按不执行动作。
5. 第3行为请求应答，第4行为当前动作；REJECT与RUN HOME可同时出现，表示新请求拒绝而旧任务仍在执行。

X右正、Y上正，范围-1000～1000。安装方向不同可改RemoteConfig.h的交换/翻转宏。中文注释重点见RemoteInput/Link/View.c。

## Gazebo验证

安装并编译配套ROS包后，先不接硬件：

```bash
roslaunch aubo_remote_bridge named_pose_gazebo.launch serial:=false
rosservice call /remote/request_named_pose "{target: home, session: 100, request_id: 1}"
# 等motion_state.state=4，再请求zero
rosservice call /remote/request_named_pose "{target: zero, session: 100, request_id: 2}"
```

接入遥控器：

```bash
roslaunch aubo_remote_bridge named_pose_gazebo.launch serial:=true port:=/dev/ttyUSB0
```

场景只用/remote_validation下的Gazebo模型、控制器与MoveIt，无真机入口。home/zero取自原SRDF，先规划执行，再按实际JointState核对到位。完整步骤见 [C++ ROS包说明](../ros1/aubo_remote_bridge/README.md)。

## 只测通信

`roslaunch aubo_remote_bridge serial_bridge.launch port:=/dev/ttyUSB0` 默认关闭命令转发，确认返回REJECT，仍可观察/remote/joy及关节反馈。Python serial_monitor.py --demo-feedback仍可用于无ROS诊断，模拟数据明确标记DEMO，不执行动作。

重连/ADC重校准第一帧只建立基线，不执行缓存请求，需重新确认。按会话/编号去重，BUSY时拒绝第二运动请求。取消需等Action确认，取消超时显示FAILED并保持锁定，不代表已停止。

未实现连续末端点动、真机接管和硬件急停。仅Gazebo请求允许运动；串口任务期间链路与输入需有效，失效会请求取消。
