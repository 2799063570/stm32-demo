# 5-1 定时器 PID + 前馈 + 编码器 + UART 目标速度

## 控制链路与资源

```text
USART1循环DMA接收 → HT/TC/IDLE中断搬运 → 主循环按换行组帧
    → Command_Parse → Control_SetTarget → 目标RPM

TIM2每10ms中断 → TIM3编码器增量 → 输出轴RPM换算 → 低通滤波
    → 目标斜坡 → 位置式PID + Kv/Ks前馈 → 抗饱和/限幅
    → TIM1_CH1 PWM + TB6612方向与STBY
```

| 资源 | 用途 |
|---|---|
| SysTick | 1ms时基，最高优先级 |
| TIM2 | 10ms固定控制周期，抢占优先级1 |
| TIM3 | PA6/PA7 AB相四倍频编码器 |
| TIM1_CH1 | PA8，20kHz PWM |
| USART1 | PA9/PA10，115200 8N1 |
| DMA1通道4/5 | USART1发送/接收，通信抢占优先级2 |

中断内不打印、不延时、不解析字符串。主循环获取状态快照后每100ms打印一次，避免串口日志改变控制周期。控制频率由硬件定时器确定；实际中断运行时间仍需在板上测量。

## 接线

按TB6612的A通道连接；模块电源、额定电流与电机供电应符合器件规格。

| STM32/电源 | TB6612/编码器 |
|---|---|
| PA8 | PWMA |
| PA4 | AIN1 |
| PA5 | AIN2 |
| PB13 | STBY；建议外加下拉，确保复位期间保持待机 |
| 3.3 V | TB6612逻辑VCC（模块须支持），兼容的编码器逻辑供电 |
| 独立电机电源 | VM，按电机和驱动额定值选择 |
| 共地 | STM32 GND、驱动GND、电机电源负极、编码器GND |
| TB6612 A01/A02 | 电机两端 |
| PA6 | 编码器A |
| PA7 | 编码器B |
| PA9/PA10 | USB-TTL RXD/TXD |

不要用STM32 GPIO直接驱动电机，电机供电不要取自ST-Link的3.3 V输出。编码器若输出5 V推挽信号，应先确认并处理逻辑兼容性；本例按3.3 V逻辑连接。

STBY低时驱动输出高阻。`Motor_Stop()` 采用待机停机，电机可能惯性滑行，**不表示主动制动或机械位置保持**。

## 文件阅读顺序

1. `User/Config.h`：硬件、周期、限幅、保护和增益。
2. `User/main.c`：初始化、命令行组帧、日志。
3. `System/Command.c`：严格解析完整命令行。
4. `System/Timer.c`：TIM2初始化和10ms中断。
5. `System/Control.c`：测速、目标斜坡、控制调度和故障管理。
6. `System/PID.c`：不依赖STM32的PID与前馈算法。
7. `Hardware/Encoder.c`、`PWM.c`、`Motor.c`、`Serial.c`：对应硬件。

## 必须按实际电机填写的参数

`User/Config.h` 默认采用下面的**演示参数**：

```c
#define ENCODER_PPR        11.0f
#define MOTOR_GEAR_RATIO   30.0f
#define ENCODER_DIRECTION  1
```

假设编码器在电机轴，每相每圈有11个原始脉冲，减速比30:1，则输出轴一圈计数为：

```text
CPR_out = PPR_motor × 4 × gear_ratio = 11 × 4 × 30 = 1320
RPM_out = Delta × 60000 / (10ms × CPR_out)
```

如果厂家标注的已经是四倍频后的CPR，不要再次乘4；如果编码器装在输出轴，则相应减速比应取1。`ENCODER_COUNTS_PER_REV` 也可直接改成实测的输出轴每圈计数。

正向PWM时测得RPM必须为正；否则交换AB相、调整电机方向定义或将 `ENCODER_DIRECTION` 改为-1。先确认方向，再提高目标，避免把负反馈接成正反馈。

10ms内实际编码器增量绝对值应小于32768，否则16位模差无法判定方向。本例每次读CNT差，不清零CNT，避免读取与清零间隙丢脉冲。只有控制中断调用 `Encoder_Get()`。

## PID与前馈

采用位置式控制：

```text
e  = ramp_target - filtered_speed
u  = Kp*e + integral - Kd*filtered_d_measurement
     + Kv*ramp_target + Ks*sign(ramp_target)
```

- 周期Dt=0.01s。Ki已乘Dt积分，Kd按测量导数计算，不是按“每次误差差值”直接套增益。
- 微分对测量值计算并低通，避免目标阶跃的微分冲击；默认Kd=0，先完成PI与前馈整定。
- Kv补偿速度对应的基础驱动力，Ks补偿静摩擦；目标为0时没有静摩擦前馈。
- 积分项自身限幅；输出饱和且误差还在推向同一饱和方向时暂停积分，允许反向误差退饱和。
- 目标默认100 RPM/s斜坡，测速低通系数0.25，输出默认限制在±600/1000（60%占空比）。
- 方向翻转时 `Motor_SetPWM()` 先关闭输出，空出一个控制周期后再按新方向输出。

这些增益没有经过你的电机实测标定。电脑的一阶模型测试用于检查软件回归，不能用于证明实际系统稳定。

## 串口协议

115200 8N1，命令以回车或换行结束，大小写敏感。支持拆成多次发送或一次发送多行，不依赖一次IDLE对应一条命令。

| 命令 | 行为 |
|---|---|
| `SPEED 60` | 输出轴正向60RPM，命令范围默认-300~300 |
| `SPEED -60` | 输出轴反向60RPM |
| `SPEED 0` | 立即待机停机，清控制器历史量 |
| `STOP` | 立即待机停机，不清已锁定故障 |
| `CLEAR` | 停机并清故障，仍保持停止 |
| `STATUS` | 不改变目标；状态会在100ms周期日志中输出 |

速度仅支持十进制整数。`SPEED nan`、`SPEED 12x`、整数溢出、范围外目标等会被拒绝，不能悄悄转换成有效速度。非法完整命令会停止控制。命令行最长63字符；超长行、非打印字节、RX丢字节或线路/DMA错误会锁定通信故障，并丢弃到下一换行重新同步。

**运行时每500ms重发一次有效SPEED命令。** 1000ms没有收到有效SPEED命令就停机并锁定超时故障。STATUS、乱码和半条命令不会喂这个通信看门狗。故障后先排除问题，再发送换行、CLEAR、有效SPEED；CLEAR本身不会启动电机。

```text
TARGET=60 RAMP=35 RPM=31 PWM=112 RUN=1 FAULT=0
```

上述为格式示例，不是实测记录。TARGET为指令RPM，RAMP为当前斜坡目标，RPM为滤波测量值，PWM为实际下发千分比，RUN与FAULT表示运行状态。

## 故障码

| FAULT | 含义 | 处理 |
|---|---|---|
| 0 | 无锁定故障 | 正常使用 |
| 1 | 1000ms无有效速度命令 | 检查周期发送，再CLEAR |
| 2 | 疑似堵转或编码器无反馈 | 检查机械、电源、编码器和阈值 |
| 3 | 持续反馈方向异常 | 检查电机/AB相方向定义 |
| 4 | 串口数据完整性异常 | 检查波特率、线路、发送量，换行后CLEAR |

默认堵转条件：控制输出绝对值≥350、斜坡目标绝对值≥30RPM，而反馈绝对值<5RPM，持续500ms。方向异常检查在启动/目标换向后留500ms宽限，再对与目标相反且正在同向驱动的反馈持续观察200ms。主动减速的反向转矩不会仅因与当前速度方向相反就判故障。

这些是教学保护逻辑，阈值需要结合低速量化、惯量和负载调整，不替代硬件过流限制和独立停机措施。

## 推荐上板顺序

1. 先断开电机供电，验证串口协议，复位时RUN=0、PWM=0、STBY低。
2. 以第四项验证编码器计数和方向，测定每圈计数，再填写Config。
3. 架空负载，降低目标和输出上限，使用限流电源。开启电机供电后，周期发送较低SPEED命令，确认RPM方向。
4. 先Kd=0，调整Kv/Ks，再调Kp、Ki；观察稳态误差、超调和PWM饱和。一次只修改少量参数。
5. 停止发送，确认约1s后进入FAULT=1、STBY低；检查STOP、CLEAR与重新启动行为。
6. 在可控条件下验证反馈异常、反转和负载变化，再提高速度。不要用未整定参数直接加载运行。
